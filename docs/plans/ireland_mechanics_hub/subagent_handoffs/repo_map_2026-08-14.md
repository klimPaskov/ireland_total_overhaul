## Primary findings

1. Ireland currently has exactly three custom scripted-GUI surfaces: Parliament, Northern Settlement, and Concealed Evidence. All three are `context_type = decision_category` panels. There is no Ireland `common/focus_inlay_windows/` implementation and no existing `national_focus_context` scripted-GUI surface.
2. The player-facing state falls into six usable families: Settlement/Parliament; Provision/Readiness; Northern Settlement; Cultural/Concealed Evidence; Foreign/Route/Conclusion; and Laws/Offices/Missions/Action Economy. The first, third, and fourth families have native panels; the other three are mainly exposed through decisions, focus tooltips, scripted localisation, flags, and gates.
3. The strongest reuse point for new actions is `ireland_sync_gui_requests` plus the existing Parliament executors and Northern/Evidence request flags. A new hub should call guarded helpers or set the existing request state; it should not duplicate decision costs or state mutation.
4. One safe semantic inlay anchor is the always-present opening focus `ireland_national_settlement` at `x = -12, y = 1` in `common/national_focus/ireland_focus_tree.txt`. Declare the new inlay in the nearby root area, but use a separate open coordinate rather than overlaying the focus itself.
5. Two source-of-truth drifts must be resolved before implementation: the docs describe fourteen Ireland decision categories while `common/decisions/categories/ireland_categories.txt` contains fifteen category blocks, and the docs/handoffs report older focus counts while the current focus source contains 256 `focus = {}` blocks. Treat source files as implementation authority until the parent reconciles the docs.

- `common/scripted_localisation/ireland_localisation.txt`, `GetIrelandConditionsSelection`, maps selection rows 1-15 to those component explanations and the Provision/Readiness/Neutrality summary rows.

Consumers and purpose gap:

- Categories `ireland_provision` and `ireland_readiness` in `common/decisions/categories/ireland_categories.txt` expose actions, while `common/decisions/ireland_decisions.txt`, focus rewards, physical-contract decisions, and route gates consume the components.

Rail, cargo, command-exercise, Belfast, and historic-site actions use explicit component thresholds.
- There is no conditions panel. This is the largest immediate purpose gap for a mechanics hub.
- Confirmed stale/misnamed consumer: `localisation/english/ireland_l_english.yml:1049` refers to bare `ireland_readiness_maritime` in a “Replace a lost merchant vessel” objective, while the canonical initialized/produced variable is `ireland_readiness_maritime_protection`. The parent should decide whether to rename the consumer or add an intentional alias; the hub should use the canonical variable.

## Existing patterns

### Existing Ireland GUI/action pattern

- Each existing scripted GUI is a separate `decision_category` context with an independent named `.gui` container and a matching category link. They use a dirty variable for property refresh and disable AI interaction (`ai_enabled = always no`, `ai_check always no`).
- Parliament buttons call guarded scripted executors directly. Northern and Evidence rows set a selection variable, increment the corresponding dirty variable, set a review/inspection request flag, and call `ireland_sync_gui_requests = yes` immediately. This is the safest action reuse boundary for a hub.
- The two 510x490 ledger panels use progressive row visibility, status icons, a selected-row dynamic explanation, and a single review/inspect action. `GetIrelandNorthernSelection`, `GetIrelandEvidenceSelection`, and `GetIrelandConditionsSelection` are reusable selector patterns.
- `context_aware_text` and scripted localisation are already used for model/stage/footer text. Keep dynamic text concise; the prior GUI handoff records renderer limitations for large context-aware strings.

### Safe hub action rules

- Use the canonical variables from `ireland_effects.txt`, not legacy aliases, for display and dirty tracking.
- Reuse `ireland_execute_parliament_*_action` for Parliament actions and `ireland_sync_gui_requests` for Northern/Evidence review requests.
- For new route/mission/law buttons, first identify the existing decision/helper that already validates costs and gates; the hub should call or expose that action, not reproduce political power, command power, burden, equipment, fuel, or threshold logic in a click effect.
- Do not use event targets in a scripted GUI; the offline Scripted GUI wiki explicitly warns that event targets are unavailable in this context. Use country variables/flags and existing helper scopes.
- Do not add a global daily/weekly on-action merely to refresh the hub. Existing dirty variables and recompute helpers already define the update boundary.
